## 1. Zero-Data Metadata Discovery Protocol

To maintain strict compliance with enterprise data governance (SOC2, HIPAA, GDPR), Fabric AI enforces a **Zero-Data Ingestion Protocol**:
* The Agent's discovery connectors **never issue `SELECT *` or query table rows**.
* All discovery is performed exclusively against **system catalogs and metadata views** (e.g. `INFORMATION_SCHEMA.TABLES`, `INFORMATION_SCHEMA.COLUMNS`, `sys.tables`, Salesforce `describeSObjects`).

```
┌────────────────────────────────────────────────────────────────────────┐
│ WHAT IS DISCOVERED (Metadata Only):                                    │
│ • Table Name & Schema (e.g., `sales.Orders`)                           │
│ • Column Names (e.g., `OrderID`, `CustomerID`, `OrderDate`, `Amount`)   │
│ • Data Types (e.g., `INT`, `VARCHAR(100)`, `DATETIME2`, `DECIMAL(18,2)`)│
│ • Primary Keys & Unique Constraints                                    │
│ • Watermark Timestamp Candidates (`ModifiedDate`, `SystemModstamp`)    │
│ • Estimated Row Counts (via table statistics)                          │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. The Ingestion Strategy Classifier (Full vs. Incremental)

The Ingestion Planner analyzes the discovered metadata to automatically categorize each table into the optimal ingestion pattern.

```
                            DISCOVERED TABLE METADATA
                                        │
                                        ▼
                           Does table have > 50,000 rows?
                                        │
                       ┌────────────────┴────────────────┐
                       ▼ YES                             ▼ NO
            Does table have a Primary Key?           FULL LOAD
                       │                             (Small lookup/reference table)
         ┌─────────────┴─────────────┐
         ▼ YES                       ▼ NO
Has Watermark Column? (Timestamp)  FULL LOAD
         │                         (No reliable incremental key)
         ├─────────────┐
         ▼ YES         ▼ NO
   INCREMENTAL LOAD  FULL LOAD
   (Delta MERGE)
```

### Classification Algorithm:
```python
def classify_ingestion_strategy(table_metadata: dict) -> dict:
    table_name = table_metadata["table"]
    columns = [c["column"].lower() for c in table_metadata["columns"]]
    row_count = table_metadata.get("estimated_rows", 0)
    pk = table_metadata.get("primary_key")

    # Watermark keyword candidates
    watermark_keywords = [
        "updated_at", "modified_date", "last_modified_date",
        "sys_modstamp", "change_time", "updated_on", "rowversion"
    ]
    matched_watermark = next((c for c in columns if c in watermark_keywords), None)

    # Decision Matrix
    if matched_watermark and pk and row_count > 50000:
        return {
            "table": table_name,
            "load_type": "Incremental",
            "watermark_column": matched_watermark,
            "primary_key": pk,
            "reason": f"High volume ({row_count:,} rows) with watermark '{matched_watermark}' and PK '{pk}'",
            "delta_strategy": "MERGE_UPSERT"
        }
    else:
        return {
            "table": table_name,
            "load_type": "Full",
            "watermark_column": None,
            "primary_key": pk,
            "reason": "Reference/Lookup table or missing reliable timestamp watermark",
            "delta_strategy": "OVERWRITE"
        }
```

## 4. PySpark Delta Lake Code Generation Engine

Based on the approved strategy, the Item Compiler generates production-grade PySpark code adhering to Microsoft Fabric best practices.

### Incremental Notebook Template (`notebook-content.py`):
```python
# Fabric notebook source

# METADATA ********************
# META {
# META   "kernel_info": {"name": "synapse_pyspark"},
# META   "dependencies": {}
# META }

# CELL ********************
# MARKDOWN
# # Ingestion: Sales_Orders (Bronze Layer)
# Auto-generated by Fabric AI Studio for Lakehouse: lh_sales_bronze

# CELL ********************
import notebookutils
from pyspark.sql import functions as F
from delta.tables import DeltaTable
from datetime import datetime

# 1. Fetch credentials securely from Azure Key Vault
KEY_VAULT_NAME = "Enterprise-Core-Vault"
SECRET_NAME = "SalesDB-Password"
db_password = notebookutils.credentials.getSecret(KEY_VAULT_NAME, SECRET_NAME)

# 2. Connection Parameters
JDBC_URL = "jdbc:sqlserver://myserver.database.windows.net:1433;databaseName=SalesDB;encrypt=true;trustServerCertificate=false"
DB_USER = "sql_reader_user"
TARGET_LAKEHOUSE = "lh_sales_bronze"
TARGET_TABLE = f"{TARGET_LAKEHOUSE}.bronze_sales_orders"

# 3. Determine Watermark
if DeltaTable.isDeltaTable(spark, TARGET_TABLE):
    max_wm_df = spark.sql(f"SELECT COALESCE(MAX(ModifiedDate), '1970-01-01') as max_wm FROM {TARGET_TABLE}")
    last_watermark = max_wm_df.collect()[0]["max_wm"]
else:
    last_watermark = "1970-01-01"

# 4. Extract Incremental Batch from Source
read_query = f"(SELECT * FROM sales.Orders WHERE ModifiedDate >= '{last_watermark}') AS src"
source_df = spark.read.format("jdbc") \
    .option("url", JDBC_URL) \
    .option("dbtable", read_query) \
    .option("user", DB_USER) \
    .option("password", db_password) \
    .option("driver", "com.microsoft.sqlserver.jdbc.SQLServerDriver") \
    .load()

# 5. Delta Lake Idempotent Upsert (Merge)
if DeltaTable.isDeltaTable(spark, TARGET_TABLE):
    dt = DeltaTable.forName(spark, TARGET_TABLE)
    dt.alias("tgt").merge(
        source_df.alias("src"),
        "tgt.OrderID = src.OrderID"
    ).whenMatchedUpdateAll().whenNotMatchedInsertAll().execute()
else:
    source_df.write.format("delta").mode("overwrite").saveAsTable(TARGET_TABLE)
```
